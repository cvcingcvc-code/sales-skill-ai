# 工作台使用手册

当前按“先开发，最后接本地模型”使用。保留 `.env` 中 `MODEL_ENABLED=false`、`LLM_PROVIDER=ollama`、`OLLAMA_MODEL` 为空即可先完成业务配置和人工客服流程。模型状态 `DISABLED` 表示主动暂停，既不是网络连通证明，也不是真实 AI 调用成功。

启动步骤见 [README](../README.md)，以后接模型见 [LOCAL_MODEL_DEPLOYMENT.md](LOCAL_MODEL_DEPLOYMENT.md)。数据库首次为空时不会自动插入真实商品。

## 管理员开始使用

1. 在本机安全配置强随机 `ADMIN_API_TOKEN`，启动 API 与 Streamlit。打开 `http://127.0.0.1:8501`，在浏览器手动输入管理员令牌。不要把令牌放进 URL 或访客聊天；后台应只通过本机或私有访问打开。
2. 在“产品与知识库”的“选择商品”中选择“新增商品”，填写名称、客观描述、价格、商品链接、上/下架状态。价格单位为人民币分，例如 12.34 元填 `1234`；新增 ID 可留空自动生成。修改时从“选择商品”加载已有记录，表单会自动回填，ID 锁定；只修改需要调整的字段，再点“保存商品”。保存成功后列表刷新并选中该记录，继续保存会更新同一商品。
3. 在“选择知识”中新建或加载商品文档、FAQ 和售后政策；编辑时会回填内容、类型、关联商品和启用状态，ID 锁定。保存后在“核对已保存的知识”中检查实际保存版本，勾选确认，再点“审核通过所选知识”。切换记录前先保存需要保留的修改。只录入自己有权使用、能够核实的业务事实，不把内部操作指令、凭据或客户资料放进知识库。启用开关和审核状态分别控制可用性；商品与知识仍视为不可信输入，模型没有改价、付款、退款或订单操作权限。
4. 用“AI 客服测试”或访客 `/chat` 检查商品列表、会话和人工流程。模型暂停时，依赖模型的商品问答会明确进入人工流程；这阶段可以测试业务闭环，真实推荐与对话效果留到本地模型启用后验收。

下架商品不会再作为可售推荐来源。修改价格、链接和政策后，重新核对答复中的引用；不能把演示脚本里的合成商品当成真实在售商品。

## 知识审核与更新

- 新知识是 `draft`（待审核），即使勾选“知识启用”也不会进入客服知识候选。后台可继续查看、编辑它。
- 审核操作仅面向已保存版本。核对标题、正文、类型与关联商品后确认；`approved`（已审核）和审核时间会持久保存。审核时不会自动把停用资料启用。
- 只有已审核、启用且关联商品仍在售的知识才能被客服检索；通用知识不要求关联商品。商品自身的上架与文案维护不属于这次知识审核流程。
- 修改标题、正文、知识类型或关联商品会恢复待审核并清空审核时间；只切换启停或不改内容地再次保存，会保留审核结果。尚未保存的输入不会作为审核依据。
- 切换知识或资料版本变化后，需要重新勾选审核确认。资料在提交审批前被改写时，旧版本审批不会生效，需要重新核对。

首次启动此版本会为旧知识表增量添加审核字段，原有内容和启停值保留，旧知识先标为待审核。升级前按[部署说明](DEPLOYMENT.md)保留一致的 SQLite 备份；升级后从原列表逐条审核即可恢复符合条件知识的检索。当前尚无有效期、冲突检测或审核人身份记录，人工审核也不构成内容准确或平台合规保证。

## 查看历史答复依据

在“客户会话”选择会话，展开商品/政策答复下的“答复依据”。这里保存的是后端当时复核、用于生成该条答复的商品和知识，包括 ID、完整描述/正文、价格、关联商品、更新时间和知识审核时间。资料后来更新或停用，不会改写该快照；它供追溯使用，不表示当前仍可按旧价格成交或旧政策处理。

消息会显示来源与保存时间。`mock_selection` 的快照另有 `MOCK` 警示，只证明离线资料选择和记录流程；`managed_catalog` 也不能单独作为真实模型端到端验收报告。规则寒暄、降级提示和人工回复没有这类模型选择快照。现有 Provider 只选择资料 ID，答复事实仍由后端渲染；快照不保存模型提示词、原始输出或全部检索候选。

[实际后台截图](demo-assets/04-answer-evidence-mock.png)使用明确的离线历史夹具；[验证记录](demo-assets/answer-evidence-verification.json)区分离线测试、真实页面和未执行的模型验收。

首次升级会给旧消息表添加可空的快照字段，旧答复正文和来源保留；没有历史快照时明确提示，不能根据当前资料倒填。快照只在管理员会话接口和后台展示，不额外返回给访客历史接口；这不会从访客已经收到的答复正文中撤回旧信息。删除会话或执行到期清理，会连同消息一起移除快照；撤回联系线索不删除它。数据库及备份仍按原隐私政策管理，这不是独立的资料版本库或防篡改审计系统。

## 访客完整体验

访问 `http://127.0.0.1:8080/chat`，先阅读对话记录及隐私告知，再开始会话。系统保存必要对话和需求摘要；不要发送密码、密钥、身份证或银行卡信息。当前匿名会话凭证用于访问自己的会话，并非账户系统；保存/分享页面信息时仍要注意隐私。

正常使用顺序：商品查询→多轮咨询→必要时自愿留资→申请人工→查看人工答复。商品与政策答复引用后台受管理记录；没有资料、投诉、退款、特殊优惠、越权请求或模型故障会进入人工处理。AI 不能承诺交易结果。

联系方式只通过专用留资表单并在明确勾选同意后保存，不从聊天中自动提取；拒绝留资不影响咨询。需要撤回时勾选确认，再使用“撤回联系线索”；这会删除该会话的联系线索，聊天记录单独管理。“关闭本次会话”表示结束本次咨询，仍可查看人工回复、撤回或删除；继续咨询应新建会话。“永久删除本次会话”需要另行确认，会删除消息、线索和接管记录，请先确认没有需要保留的业务处理。“开始新会话”只清除本浏览器对旧会话的访问凭证，不会删除服务器历史记录。

模型主动暂停时，商品列表和后台事实仍可查询，规则寒暄可以直接回复；模型问答显示 `DISABLED` 并转人工。`MOCK` 仅表示自动化测试或合成演示，不能用于宣称真实模型可用。

## 处理人工队列

1. 管理员打开“人工接管队列”，检查待办、客户会话和需求摘要。
2. 根据受管理资料答复。涉及优惠、支付或退款，先走商家的后端权限与人工审批流程；工作台本身不执行这些交易。
3. 提交人工回复后，访客可在自己的会话中刷新查看。接管条目变为已处理，但会话继续保持人工模式，避免 AI 抢答。
4. 需要继续 AI 时，先处理该会话全部 `pending` 条目，再到“客户会话”选择“恢复所选会话的 AI”；存在待办时后端会拒绝恢复。模型尚未启用时恢复 AI 也不会使真实调用可用。
5. 已完成的问题可以选择“关闭所选会话”；关闭会同时结束尚未完成的接管条目。不要将关闭会话误作删除客户资料。

## 客户资料与保留期限

“客户会话”可核对消息、需求摘要及已同意的联系线索。管理员的删除/撤回操作同样需要授权，不要把敏感会话截图、数据库、备份或联系信息提交 Git。

数据管理提供两种不同范围：撤回/删除联系线索只移除留资记录；删除会话同时移除该会话的消息、接管、线索和模型用量详情。固定审计事件保留操作类型、执行角色、哈希对象标识和时间，不保留原消息或联系方式。全局调用预算计数不会因删除单个会话而重置。

“隐私与审计”中的保留清理默认只预览。选择保留天数，点击“预览到期数据”，核对候选数量、最近备份和处理状态，再勾选当前预览的确认框，点击“永久清理到期数据”。更改天数或完成清理后需重新预览。清理只处理“已关闭、最后活动超过保留期限、没有待办接管”的会话；开放和待办会话不会被这一批处理。系统未替商家决定合适期限，也未默认安装定时清理任务。实际使用时应把数据库文件、SQLite WAL 及备份副本一并纳入访问、备份轮换和删除政策；应用删除不保证历史备份或磁盘上的法证清除。

## 模型状态与资源限制

后台“模型状态和调用成本”用于查看当前配置和实际调用状态。`configured` 只表示前置配置存在；必须有真实请求结果才可能报告实际可用。`DISABLED` 是主动暂停，`BLOCKED` 表示配置、网络、服务或预算等条件阻断，不能算通过。

| 配置 | 含义 |
| --- | --- |
| `MODEL_ENABLED` | 显式模型开关；本轮保持 `false` |
| `MODEL_DAILY_CALL_LIMIT` | 客服模型请求每日次数上限，按 UTC 自然日；失败尝试也会占用次数 |
| `MODEL_DAILY_TOKEN_LIMIT` | 客服每日 token 预算；调用前按输入/输出上限预留，有完整有效用量时再结算 |
| `MODEL_MAX_INPUT_TOKENS`、`MODEL_MAX_OUTPUT_TOKENS` | 单次输入与输出边界；本地小模型建议先 `4000` / `1024` 试起 |
| `SUPPORT_MODEL_MAX_OUTPUT_TOKENS` | 客服资料选择器专用输出上限，默认 `512`，并受 Provider 通用输出上限约束 |
| `MODEL_DAILY_COST_LIMIT` | 可选的每日估算金额上限；启用时必须配置对应 Provider 有效输入/输出单价 |
| `OLLAMA_INPUT_PRICE_PER_MILLION`、`OLLAMA_OUTPUT_PRICE_PER_MILLION` | 可选本地计价口径，不自动假定为零，也不代表设备实际成本 |

按 UTC 的预算日与中国本地日期边界不同，对应北京时间每天 08:00 切日。缺失用量或失败请求会保守保留预留额度；没有价格配置时显示未知费用，未知不等于零。金额只是同一配置币种下的估算，不是账单。

API 另有限流，频繁创建会话或发送请求会收到 `429`；按提示稍后重试。应用限流不能替代公网反向代理、连接限制与访问控制。配置修改后重启进程，必要时在新环境中验证，不能只看配置页面就认定已生效。

## 保留原销售训练

“销售训练”与原 CLI 继续提供场景、难度筛选、角色扮演及评分。模型评分和规则评分应按界面标识区分；规则分数只表示启发式匹配，不代表真实模型或人工评分。模型关闭时不把占位结果当作真实对话/评分。

新评分维度采用 0–20，总分 0–100；能力画像将有明确量纲的维度分归一为百分制，再按 70 分判断薄弱项，例如 `14/20` 对应 `70/100`。历史记录不会批量重写；缺少量纲的旧分数保留原值并标记未核验，不自动换算，也不加入归一化雷达图。缺量纲的 0–20 分不作弱项判断；为兼容原有手工记录，`20 < score <= 100` 的旧分仍沿用 70 阈值，这不证明原量纲，其弱项结果不能视作已核验能力结论。每次训练后的结果是否来自真实模型，以来源标识及该次调用状态为准。

## 遇到问题

| 情况 | 处理 |
| --- | --- |
| 管理员入口 `BLOCKED` / 无法登录 | 安全检查令牌是否已配置、API 和工作台是否读取同一值，然后重启；不要打印令牌 |
| `DISABLED` | 当前符合“最后接模型”的预期；继续录商品和处理人工 |
| 本地模型启用后 `BLOCKED` | 确认 Ollama 已启动、`ollama list` 标签与配置相同、后端可达和预算未耗尽，运行真实验收脚本 |
| `FAIL` 或答复不符合资料 | 保留脱敏复现步骤，补测试后修复；不要切 Mock 宣称成功 |
| 无商品或知识可引用 | 管理员检查商品上架、知识审核与启用状态、内容和关联；没有足够资料时转人工是预期行为 |
| 无法恢复 AI | 先处理全部待办人工接管；关闭会话须新建，不能恢复为开放聊天 |
| 清理候选为零 | 检查是否已关闭、是否超过最后活动保留期限，以及是否仍有待办；不要放宽条件去删除开放会话 |

未来公开访问前，按 [DEPLOYMENT.md](DEPLOYMENT.md)完成 HTTPS、私有后台、持久化数据库、备份及小流量验收。本轮未上线公网，也未验证真实商家资料或本地模型回答效果。
