# V2 交付状态与后续步骤

V2.1 继续优化现有工作台：知识相关性与商品政策关联、预算前的无网络请求预检、GitHub 离线回归门槛。优先级及以后推进方式见 [OPTIMIZATION_PLAN.md](OPTIMIZATION_PLAN.md)，开发和自动同步约定见 [DEVELOPMENT.md](DEVELOPMENT.md)，本轮实测见 [ACCEPTANCE_REPORT_V2_1.md](ACCEPTANCE_REPORT_V2_1.md)。以下保留 V2 的业务与本地模型部署路线，模型仍保持暂停。

本轮按“应用先完成，最后接本地模型”推进：保留 V1 培训与客服工作流，默认配置切换为 `MODEL_ENABLED=false`、`LLM_PROVIDER=ollama`、`OLLAMA_MODEL` 为空。真实模型接入延后，不要求先提供云端 API Key，也不安装 Ollama 或下载权重。实现与限制见 [ARCHITECTURE.md](ARCHITECTURE.md)，本轮实测以 [ACCEPTANCE_REPORT_V2.md](ACCEPTANCE_REPORT_V2.md) 为准；[ACCEPTANCE_REPORT.md](ACCEPTANCE_REPORT.md) 保留为 V1 历史记录。

## 本轮应用范围

| 已建设能力 | 使用与验证边界 |
| --- | --- |
| 统一模型网关、显式暂停、输入/输出边界和本地优先配置 | 暂停是 `DISABLED`；没有真实调用就不能声称本地模型可用 |
| 商品、文档/FAQ/政策、会话、需求及知情同意留资 | 实际商家须录入并审核资料；测试商品不代表真实可售 |
| 人工队列、回复、明确恢复 AI、关闭会话 | 所有待办处理后才能恢复；人工回复不会自动抢回 AI |
| 同意撤回、线索/会话删除、保留清理预览和执行、无正文审计 | 只对符合条件的已关闭会话清理，默认先预览；备份和实际保留期限由部署方制定 |
| 请求限流、UTC 每日次数/token 预算、可选估算金额预算 | 预算使用保守预留；价格缺失显示未知，不能冒充零成本；公网仍需代理层保护 |
| 原销售训练、难度筛选回归、评分量纲与来源说明 | 规则评分不等于模型评分；真实角色扮演及模型评分以后单独实测 |
| Windows/macOS/Linux 本地模型通用说明、离线预检和使用手册 | 预检不请求模型，`OFFLINE_READY` 不等于真实模型验收通过 |

使用步骤见 [USER_GUIDE.md](USER_GUIDE.md)。本轮到上述范围停止，不增加外呼、支付退款自动化、模型微调、复杂前端或多智能体功能。

## 最后完成模型与真实业务验收

| 下一步 | 由谁处理 | 完成依据 |
| --- | --- | --- |
| 确认实际电脑与系统资源 | 本机操作者 | 记录可用 RAM/VRAM、磁盘、系统、预期并发；目前设备未确定，先使用通用部署说明 |
| 按官方说明安装 Ollama，并只下载一个合适的小模型试运行 | 本机操作者 | 官方安装来源、服务运行、`ollama list` 有准确标签；不以参数量保证性能 |
| 配置本地地址/模型和资源上限，最后显式启用并重启 | 本机操作者 | 按 [LOCAL_MODEL_DEPLOYMENT.md](LOCAL_MODEL_DEPLOYMENT.md)配置；无须云端 API Key |
| 运行真实 Provider 与合成客服验收 | 已配置本机操作者 | `scripts/verify_live.py --provider ollama` 退出码 0 且报告 `PASS`；关闭、网络/服务故障保留 `BLOCKED`，格式/业务错误保留 `FAIL` |
| 录入第一批真实商家商品及已审核政策 | 商家管理员 | 价格、链接、上下架及政策逐条审核；不得使用验收脚本的合成商品对外销售 |
| 用真实业务问题验证模型和人工闭环 | 商家与开发者 | 核对引用、推荐、未知问题、错误价格诱导、同意留资、人工回复/恢复、删除和预算；保留脱敏复现记录 |
| 建立小流量网站的访问与运维条件 | 部署方 | 按 [DEPLOYMENT.md](DEPLOYMENT.md)配置 HTTPS、私有后台、持久数据库与备份；云到本地模型只走安全私有连接，模型机离线能转人工 |

真实报告保存在仓库外，更新验收文档时只记录脱敏结果，不提交凭据、客户资料、数据库或权重。模型行为不符合资料选择/评分合约时，应记录失败并补测试；不能使用 Mock 将真实失败改写成成功。

## 保留的长期事项

DeepSeek 云端 Provider 仍作为可选显式切换路径。若以后启用，账户持有人需先核验 [SECURITY.md](../SECURITY.md) 中历史凭据的撤销/轮换，再安全配置新密钥及当前模型/API 地址；历史轮换状态目前未验证。本地方案无需先解决云模型配置才能继续应用开发。

单机 SQLite、单 worker、关键词检索继续作为当前边界。先根据真实咨询记录优化资料与检索，再根据实际并发、质量或可用性瓶颈决定是否升级数据库、部署常在线模型机或采用更复杂检索；不提前扩展架构。
