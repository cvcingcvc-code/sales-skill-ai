## 推进建议

1. **保留最小资料治理范围**：选中回填、知识审核、答复快照和内部来源记录已完成。后续如继续开发，可单独评估知识有效期与过期不引用这一小阶段，不混入冲突治理或平台规则。
2. **保留本机模型验收门槛**：按用户安排留待真机阶段；没有真实模型证据就不要宣称自动 AI 客服完成。
3. **在实际设备完成重启验收**：模型调用之后，验证进程重启不会丢商品、知识、会话和人工队列。
4. **最后用虚构店铺案例试用**：关注答复是否符合商品事实、未知问题是否接管、人工处理是否顺畅。

如果用户电脑已有兼容模型且服务可达，P0 验收通常可安排在半天到两天的调试窗口；如果还要评估硬件、安装服务和下载权重，耗时主要由设备、网络和权限决定，目前无法给出可靠日历时间。有效期等剩余资料治理应另选最小阶段，不再把已实现的审核、来源记录和答复快照重复计为未完成。公网生产不是本地 MVP 的完成条件。

另有一项不阻断验收的技术债：当前 Streamlit 测试输出提示 `use_container_width` 参数将被移除，另有 AppTest 裸运行上下文告警。476 项回归仍通过；可在单独的 UI 兼容性小阶段处理，不应抢在真实模型和资料可追溯性之前。
